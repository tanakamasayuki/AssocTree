# TypeChecks

> English: [README.md](README.md)

保存した型を確認してから値を変換するサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [TypeChecks.ino](TypeChecks.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<Arduino.h>`, `<AssocTree.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

setupで必要な設定と最初の処理を行い、loopでは例の待機または継続処理を実行します。結果の観察と処理の終了は、下の注意点とソースの条件を対応させて確認してください。

## APIの使い方と注意点

内部領域の `AssocTree<bytes>` または外部領域を渡す `AssocTree<0>` を選びます。外部領域はツリーの利用中ずっと保持し、PSRAMの有無と代替確保の成否も確認します。添字の連鎖はパスを表し、代入でデータが作られます。

`.as<T>(fallback)` は代替値を返す仕組みで、元の型が正しいという証明ではありません。形式が重要なら型判定も行います。`unset()`／`clear()` は論理内容を削除し、`gc()` は領域を詰め直して既存の参照を無効にするので、NodeRef・イテレータ・文字列viewを取り直します。

データを増やす場合はシリアライズ成否と空き容量を確認します。Stringへの出力や外部領域の確保は、固定プールとは別にメモリを使います。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text
 exists=
 type=
Null
```

## 確認と問題の切り分け

保存した型を確認してから値を変換することを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
